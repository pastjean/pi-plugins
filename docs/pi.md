# Running pstack in Pi

Start a workflow with `/skill:poteto-mode <task>`, or invoke a specific skill such as `/skill:architect`. Use real skill names from the package. A skill command adds instructions to the current session; it does not start a persistent mode, service or new process. When a step calls another skill, read `skills/<name>/SKILL.md` relative to the installed package and follow it in the same task. Do not issue slash commands through the shell.

- **Tool names:** use the tools advertised in the current session. Stock Pi provides file and shell tools. If there is no todo tool, keep a short checklist in the conversation. If there is no question tool, ask in plain text. Search with available file tools or `rg`.
- **Models:** use the active session model by default. Optional role preferences belong in `pstack-models.md` under `PI_CODING_AGENT_DIR` (default `~/.pi/agent`). This is pstack data, not an automatically loaded Pi rule. Read it only for role selection. Do not change the active model, enable providers or write credentials on the user's behalf.
- **Delegation:** a skill does not grant permission to delegate. Use an installed subagent capability only when authorized. Pass a supported model and fields from its actual schema. `agents/` contains role briefs, not installed tools. Without workers, do eligible work inline and identify it as such. If independent or multi-model evidence is required, leave that gate open. A worktree is not a cloud agent.
- **User data:** inspect only the relevant project and session. Ask before reading other session history, persisting personal preferences or sending workspace content to another service. Never dump tokens or session state into a public artifact.
- **External actions:** a suggested playbook is not authorization to publish, merge, clean worktrees, deploy, or schedule a job. Check the requested scope, repository, branch and available service before acting. Stock Pi does not provide Cursor Automations, Bugbot, a browser, or a background scheduler. If a service already reports on the target PR, its results are evidence, not permission to start another job.
- **Verification:** report what ran, what passed, and what could not run. If a required gate is missing, say what would unblock it. Do not convert a skip or an inline review into an independent pass.
