# Pi pstack implementation plan

**Goal:** Install the port with `pi install git:github.com/pastjean/pi-pstack` and start a task with `/skill:poteto-mode`.

**Architecture:** A Git package with a `pi.skills` manifest, Markdown skills, shared Pi instructions, and upstream helpers. No extension at startup.

**Tech stack:** Pi, Markdown, Node.js for package tests. Keep optional helper runtimes local to their skills.

**Spec:** [Pi port design](../specs/2026-11-24-pi-port-design.md)

## Global constraints

Preserve the upstream MIT notice and pin provenance. Keep personal settings and source projects out of the repository. Use upstream's 59 skill definitions and 22 playbooks as the coverage inventory.

## Review focus

Broken relative paths outside the checkout; hidden or duplicated skill commands; tool or model claims on stock Pi; unapproved writes to personal settings; an unavailable independent check treated as a pass.

## 1. Package and route

- [ ] Add `package.json` with `pi.skills: ["./skills"]`, `LICENSE`, `README.md`, and the pinned source reference.
- [ ] Adapt `skills/*/SKILL.md` and cross-skill calls to Pi discovery and `/skill:<name>`. Keep dependencies and playbooks relative to their skill paths.
- [ ] Check the inventory, frontmatter, local links and router targets with a package test. Check a renamed target makes the test fail.

## 2. Remove host assumptions

- [ ] Rewrite setup, model selection, role briefs and transcript discovery for Pi. Read optional settings only from their documented scope; do not edit global instructions as part of installation.
- [ ] Map supported operations to Pi tools; gate agent panels, cloud jobs and forge operations on authorization and capability. Name unavailable evidence and stop when it is required.
- [ ] Inspect setup, authoring, review and cloud-only paths against a stock install. Check direct invocation does not depend on first running the router.

## 3. Install and publish

- [ ] Exercise `pi install` with temporary Pi state. Inspect Pi's actual command list over RPC for the installed skills. Run affected helper tests separately; distinguish skips from passes.
- [ ] Commit and push to `main`. Repeat the install check from the public Git URL and confirm `origin/main` matches the tested commit.
